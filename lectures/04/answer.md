- 結果：
  - 一致率：根拠 8/10、範囲 9/10、ヒント 10/10、分かりやすさ 9/10、回の表示 9/10、総合 9/10（coverage 100%、要確認 0 件）

    - #09 根拠（LLM fail／自分 pass）：LLM が「範囲外の案内が不足している」という範囲の問題を根拠に持ち込んでいる（演習の #06 と同じ、基準をまたいだ混同）。範囲は自分も LLM も fail で一致
  - 分かった自分のエージェントの弱点
    - #09 では転職相談にそのまま答えた。`INSTRUCTIONS` に「講座外の質問は断る」という指示がなく、rubric で測っている基準がエージェントへの指示に入っていなかった
    - 回の表示が #06・#09・#10 で抜けていた。#01 は APIキー（第1回の用語）の話なのに「第3回」と書いていて、コード判定は pass になる
    - #08 は、エージェントは指示どおり承認待ちで止まっていた（勝手に保存はしていない）。ただし評価用の `--generate` が承認待ちを処理せず、そのまま文字列にしていた。評価のハーネスが、エージェントの機能に追いついていなかった
- コードで判定した方がよい基準と、LLM に任せる基準の使い分け：
  - コードに向くもの（形式・文字列・実行の記録で決まり、ぶれてほしくないもの）
    - 回の表示：末尾に「第N回」があるか。今回の #09 のように人は甘く読んでしまうので、コードの方がぶれない。さらに N が 1〜13 の範囲かもコードで見られる（講師の #10 の第14回を落とせる）
    - 出力が壊れていないか：`DeferredToolRequests(` のような内部表現や空の回答は文字列で検出できる。LLM は #08 を見抜けなかったので、ここはコードで先に落とすべき
    - 取り消しにくい操作の確認：保存のツールが承認なしで実行されたかは、回答文ではなくツール呼び出しの記録（trace）を見れば確実に分かる
    - 指示文の漏れ：`INSTRUCTIONS` の文がそのまま回答に含まれているかは、文字列の照合で見られる
  - LLM に任せるもの（意味の判断が要るもの）
    - 根拠：用語集と矛盾しているか、断定しているかは言い換えを含めて意味で見る必要がある
    - 範囲：講座に関係ありそうに見える質問（#09 の転職相談）が範囲外かどうか
    - ヒント：コードがないから合格、とは言えない（#07 のように記述問題の解答文もある）
    - 分かりやすさ：主観的で、文字数などの目安はコードでも見られるが、最後は意味の判断になる
  - ただし LLM に任せる基準でも、#01・#09 の根拠のように基準をまたいだ判定が起きるので、一致率と不一致の理由を人が読む工程は外せない
- 気づき・疑問：
  - 今の 5 つの基準には「出力が壊れている」を捕まえる基準がなく、人も LLM もどこで落とすか迷った。採点の前に、コードで「回答として成り立っているか」を見る門番の基準が要る
  - 評価してみて初めて、「講座外は断る」がエージェントの指示に入っていないことに気づいた。評価の基準とエージェントへの指示は、同じものから作って対応させておくべき
  - 回の表示のような形式の基準は、人が付けると甘くなりやすい（演習でも今回でも、意味で読んで pass にした）。人がラベルを付けるときも、形式の基準は機械的に読むか、最初からコードに任せた方がよい

### 発展：GPQA Diamond を調べる

- データセット：GPQA（A Graduate-Level Google-Proof Q&A Benchmark）の Diamond サブセット
  - 論文：https://arxiv.org/abs/2311.12022
  - データ：https://huggingface.co/datasets/Idavidrein/gpqa （利用規約への同意が必要。作者は、学習データへの混入を防ぐため問題をそのままネットに載せないよう求めていて、データには canary string が埋め込まれている。なので以下は要約だけを書く）
- 中身：生物学・物理学・化学の博士レベルの 4 択問題。Diamond は 198 問（全体 546 問 → Main 448 問 → Diamond 198 問）。「Google-Proof」とは、専門外の人がネット検索を使っても解けないように作ってあるという意味
- 読んだ問題の要約（Diamond から生物・物理・化学を 1 問ずつ。問題文は載せず要約で書く）
  1. 生物（分子生物学、作問者の難易度見積もり：博士取得後レベル以上）
     - 内容：SARS-CoV-2 の分子生物学について、論文に基づく 4 つの長い記述（リボソームフレームシフト、シュードノット、ORF3a によるアポトーシス、nsp10/nsp14 のエキソヌクレアーゼ）から、誤っているものを 1 つ選ぶ。誤りの記述は、本来「二本鎖 RNA を分解する」ところを「分解を防ぐ」と 1 か所だけ逆にしてある
     - 自分なら解けるか：解けない。論文ごとの細かい結論を知らないと、どの記述が逆になっているか見分けられない（専門外の知識は高校レベルで止まっている）
     - LLM の難しさ：それぞれの記述がもっともらしい専門用語でできていて、誤りは 1 語の反転だけ。個々の論文の細かい結論を正確に覚えていないと見分けられない。一方で、専門家の 1 人目は「1 つ目の選択肢が確認しやすいので簡単すぎる」とコメントしていて、専門家とそれ以外で難しさの感じ方が大きく違う
     - 検証：専門家 2 人とも正解、非専門家は 3 人中 1 人だけ正解
  2. 物理（量子力学、作問者の見積もり：学部上級レベル）
     - 内容：スピン 1/2 の粒子が上向きと下向きの重ね合わせ状態にあるとき、σz と σx を組み合わせた演算子の期待値を小数第 1 位まで求める（答えは負の値）
     - 自分なら解けるか：解けない。スピンや演算子の期待値は高校の物理では扱わず、何を計算すればよいかも分からない
     - LLM の難しさ：手順自体は教科書どおりで、各成分の期待値を計算して足すだけ。難しさは、符号や係数を間違えずに計算を最後までやり切れるかにある。専門家の 1 人目は「ほぼ同じ問題がネットにある」と指摘し、作問者が数値を変えて直していた。数値を変えただけの問題は、学習データに似た問題が入っているモデルには解きやすいかもしれない（Google-Proof を保つのが難しい例）
     - 検証：専門家 2 人とも正解、非専門家は 3 人中 1 人だけ正解
  3. 化学（有機化学、作問者の見積もり：大学院上級レベル）
     - 内容：ある芳香族アルデヒドに、3 段階の反応（グリニャール試薬の付加 → 酸化 → 硫黄イリドによるシクロプロパン化）をかけた最終生成物の炭素数を答える
     - 自分なら解けるか：解けない。試薬の正式名から何の反応かが分からず、生成物の構造を追えない
     - LLM の難しさ：段ごとに生成物の構造を正しく追い、どの段で炭素が増えるか（1 段目と 3 段目で 1 つずつ増える）を数える多段の推論。試薬が略称でなく正式名で書かれていて、何の反応か分かること自体が知識を要する。非専門家は 3 人とも不正解
     - 気づいたこと：問題文で「生成物 2 を反応させる」はずのところが「3 を反応させる」と誤記されたまま Diamond に残っていた。専門家 2 人の検証を通っても、問題文の誤りが残ることがある
- 作成の人数と手順
  - 人数：Upwork で 61 人を雇った。条件は、その分野の博士号を持っているか博士課程に在籍していることと、英語が堪能なこと。時給は平均で約 95 ドル（最大 150 ドル）で、報酬の大半は品質に応じたボーナス
  - 手順
    1. 専門家が、問題・選択肢・解説を書く
    2. 同じ分野の 1 人目の専門家が解いて、フィードバックを返す
    3. 作問者がフィードバックを受けて問題を直す
    4. 2 人目の専門家が、直した問題を解く
    5. 別分野の専門家 3 人が「非専門家」として解く。ネット検索は自由（LLM は禁止）で、1 問に最低 15 分かける（平均 37 分）
  - 選別：564 問を集め、Diamond には「専門家 2 人とも正解（または 2 人目の誤りが明らかなミス）」かつ「非専門家の正解が 3 人中 1 人以下」の問題だけを残した。ChatGPT を使っていた作問者の問題や、質の低い問題は除いた
  - 報酬の設計：作問者は「専門家が正解するたび」と「非専門家が間違えるたび」にボーナスがもらえる。正解がはっきりしていて、かつ専門外には難しい問題を作る動機が、報酬そのものに組み込まれている
  - 採点：4 択の正解率。モデルの回答から「answer is」などの表現を正規表現で取り出して、正解と照合する（LLM による採点は使わない）
  - 難しさの目安（Diamond）：専門家 81.3%、非専門家 22.1%、GPT-4（few-shot CoT）38.8%、ランダムに選ぶと 25%（専門家と非専門家の数字は、この条件で選別したので高め／低めに偏っている）

  - GPQA は「正解が 1 つに決まる」ように、専門家 2 人に解かせて答えが割れた問題を捨てている。今日の評価は逆に、分かりやすさのように人同士でも割れる基準をあえて残し、割れ方を見ていた。正解を作れる問題はコードで採点でき、作れない問題は LLM と人で採点して一致率を見る、という今日の使い分けがベンチマークの作り方にも表れている
  - 今日、演習の 10 件では、1 件の判定が揺れるだけで一致率が 10% 動いた。GPQA でも Main の 448 問は「小さな性能差を見分けるには少ない」と論文の限界に書かれている。件数が少ない評価で差を語るときは、揺れの幅を先に見るべき
  - 報酬で問題の質（正解が明確で、専門外には難しい）を誘導しているのが面白い。自分の評価セット作りでも、「どういう問題が良い問題か」を先に決めて、それを満たさない問題は捨てる手順が要る
  - 3 問とも、専門外の自分には手も足も出なかった。専門外の知識は高校レベルで止まっていて、何を問われているかを理解するところで止まる。論文の「非専門家」は別分野の博士レベルの人で、ネット検索ありで平均 37 分かけても Diamond の正答率は 22%（4 択のランダムより低い）。この難しさが、専門家の検証付きの数字として示されているのがベンチマークの価値だと思った
  - 疑問：4 択は 25% が当てずっぽうで取れる。モデルの性能が専門家を超えてくると、この形式で差を測れなくなるのではないか
