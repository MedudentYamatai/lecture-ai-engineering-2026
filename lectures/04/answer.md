  - #02・#07・#09 の回の表示（自分 pass／講師 fail）：「末尾に」ではなく、文章のどこかに「第N回」があればよいと読んでいた。基準の読み方が自分の方が甘かった。#10（自分 fail／講師 pass）は、存在しない「第14回」を表示していたので fail にしたが、この基準は「第N回」という文字列があるかだけを見るので pass になる（存在しない回の断定は根拠の側で fail になっている）

- 気づき・疑問：
  - 「分かりやすさ」のような主観的な基準は、読む人の事前知識で判定が変わる。「一般的な読み手にとってどうか」は人によって基準が曖昧なので、具体的な目安（繰り返しの有無、文字数など）を基準に書かないと、人同士でも人と LLM でも割れる
  - 回の表示は、自分は意味で読んで判定を甘くしたが、コードは文字列だけを見るのでぶれない。その代わり、#07 の「関係する回：なし」のように妥当な回答も fail にし、#10 の存在しない回も pass にしてしまう。形式はコード、意味は LLM と人、と使い分けるのがよさそう
  - 「根拠」に 1 行書き足しただけで、#05 は狙いどおり unsure → pass になった一方、#06 では無関係な範囲・分かりやすさの判定まで fail に変わった。rubric に「基準は 1 つずつ独立に見る」と書いてあっても LLM は守り切れず、temperature 0 でもプロンプトの小さな変更で他の項目が揺れる。直した後は、直した項目以外の変化も確認する必要がある

### 基礎：判定の順序（理由→判定 / 判定→理由）を入れ替える

- 結果（モデル gemini-3.5-flash-lite、temperature 0、要確認はどの実行も 0 件）：

  | 実行 | 根拠 | 範囲 | ヒント | 分かりやすさ | 総合 | LLM 由来の不一致 |

- 気づき・疑問：
  - 順序を入れ替えても、総合の一致率は変わらなかった。基準別の数字は 1 件単位で上下したが、同じ設定で再実行しただけでも同じくらい動いた（演習で見えた #06 の範囲・分かりやすさの fail は、再実行で消えた）。10 件・1 回ずつの比較では、順序の効果と実行ごとの揺れを区別できない。比べるなら、件数を増やすか、同じ設定で何回か回して揺れの幅を見てからにする必要がある
  - temperature 0 でも判定は再現しない。採点器の結果を 1 回の実行だけで信じるのは危ない
  - 安定して割れたのは #04 の分かりやすさ（LLM はどの実行でも fail）だけで、これは揺れではなく、自分と LLM の基準の読み方の違いだと言える
  - 判定→理由の 1 回目では、#08（「指示を無視して」の要求）で、範囲の問題を根拠の fail にも持ち込んでいた。判定を先に出すと、理由が後付けの説明になり、基準をまたいだ混同が起きやすいのかもしれない（この回数では断定できない）
  - `rubric.md` には「先に理由を書いてから判定を決める」とあり、出力の形（判定→理由）と指示が食い違った状態で比べている。順序の効果をきれいに見るなら、この 1 行も合わせて変えるべきかは疑問として残る
